# Native full-transit deployment candidate

This is a **local, unrun deployment candidate**, not evidence of Databricks ingestion or live arrivals. It packages the official public scheduled BT GTFS capture at `data/campus/transit-full/`. No credential, upload, job submission, or cloud write is performed by the generator.

Render/preview: `node databricks/full-transit-native.mjs` prints a summary. `node databricks/full-transit-native.mjs --output /tmp/beacon-full-transit.py` writes a new local notebook (refuses overwrite). `node --test databricks/full-transit-native.test.mjs` runs local tests. Local `python3` with the standard library and the repository's `databricks/ingest/full_transit.py` importer are required: the generator re-derives every normalized table from the authenticated source ZIP and rejects mismatches, including same-count time or service-epoch edits. Review the generated notebook, table grants and workspace execution environment before any approved deployment.

The fixed managed Delta targets in `workspace.beacon` are `transit_stops`, `transit_routes`, `transit_trips`, `transit_stop_times`, `transit_service_trips`, `transit_source_archive`, and `transit_imports`. All are keyed by `source_sha256`, then their natural stop/route/trip/sequence/date keys. `transit_imports` is the completion marker and merges last, after every preceding table's source-version row count is verified. Re-running a version is insert-only/idempotent; a failed partial version has no completion marker. The candidate does not delete or replace previous versions. Only fixed identifiers appear in SQL; source text is contained in a compressed payload. Numeric coordinates, GTFS elapsed seconds, stop sequence, and pickup/drop-off types are typed columns. Service date and UTC service epoch are DATE and TIMESTAMP columns.

`databricks/sql/full-transit-direct.sql` is a parameterized *direct scheduled journey* query. The consumer must bind public `from_stop_id` and `to_stop_id` strings, explicit independently verified `access_seconds` (0–10,800), and UTC `evaluated_at`. It returns zero or one row: source hash, service date, trip and route IDs/names, boarding/alighting occurrence sequences, UTC departure/arrival timestamps, `transfers=0`, and `source_kind='scheduled'`. Zero rows means no verified direct scheduled journey within the three-hour evaluation horizon or no completed fresh feed. A boarding departure before evaluated time plus verified access is excluded; pickup/drop-off restrictions and occurrence order are enforced. The query does not infer pedestrian access, transfers, live vehicle position, or realtime arrival. It is not a new server API or agent field. Capture freshness and indexed service window gate the query; a stale or expired capture must not be presented as current.
