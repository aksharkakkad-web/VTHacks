# Complete Blacksburg Transit schedule capture

`python3 databricks/ingest/full_transit.py --start-date 2026-09-19 --days 14` captures the official [BT GTFS archive](https://www.bt4uclassic.org/gtfs/google_transit.zip) into `data/campus/transit-full/`. The date is an explicit agency-local service date, not a hardcoded runtime assumption; select a fresh start date when refreshing. The raw `source.zip` and its SHA-256 are retained, alongside normalized JSON for agency, all stops/routes/trips/stop times, calendars, exceptions and feed metadata. The compact `service_trips.json` contains one row per active trip and service date, not a table of all stop pairs. The manifest records capture time, complete row counts, 14-day horizon and rights caution.

Captured 2026-09-19 17:00 UTC, SHA-256 `aed7634f4df2e942f1af101c24d05f53e2b8686013f0bbe843b0e1c8dd34dd85`: 1 agency, 297 stops, 24 routes, 3,658 trips, 74,301 stop times, zero weekly calendar rows, 181 dated calendar exceptions, one feed metadata row. The 2026-09-19 through 2026-10-02 index contains 10,456 trip-date records. This particular official feed is exceptions-only, with exception dates from 2026-08-01 through 2026-12-30; dates without added service legitimately have no trips. Agency timezone is America/New_York. Service times over 24:00 are converted from the agency service-day epoch (local noon minus 12 elapsed hours), including DST transitions.

`direct_journey(data, from_stop_id, to_stop_id, ready_at, access_minutes=0)` returns the earliest-arriving feasible scheduled same-trip ride or `None`. Use `import_archive(raw, start, days)` for a fresh in-memory capture; for saved JSON, load the table files into a dict and set `source_sha256` to the manifest's `sha256`. It checks ordered stop occurrences (including loops), pickup/drop-off restrictions and access time before boarding. It accepts arbitrary stop IDs actually present in the verified feed; unknown stops and reverse-only trips yield no itinerary. `None` does not imply a route is impossible via a transfer: transfers, live arrivals, disruptions, walking network routes and egress estimates are unsupported. A scheduled result is not a live availability or safety guarantee. The existing two-corridor runtime importer remains unchanged and is not automatically replaced by this capture.

Refresh from the official source before use: rerun with an explicit current service-date start and at least 14 days, inspect changed source hash/counts and feed dates, and verify relevant service dates are populated. The import overwrites only the dedicated full-transit capture on success; do not infer live availability from an old source hash. Attribution is retained; review BT source terms before redistribution beyond this demo. No credentials or student-location data are stored.

Fixture verification: `python3 -m unittest discover -s databricks/ingest -p test_full_transit.py`.
